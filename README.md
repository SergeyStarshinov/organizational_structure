# API организационной структуры

## Запуск проекта
Проект запускается командой `make`. Makefile запускает две команды:
- `docker pull postgres` для скачивания образа контейнера для базы даннх
- `docker compose up -d` запускает проект в Docker
Запуск тестов через `make test` настроен только для запуска на хосте, требует доступности базы с названием `hitalent` с таблицами `departments` и `employees`. Не сбрасывает данные, но по окончании теста удаляет все департаменты, названия которых начинаются на "test"

## Описание проекта

- `cmd` содержит файл `main.go`
- `config` содержит файл с параметрами запуска приложения: 
  1. адрес и порт сервера, 
  2. настройки подключения к базе данных, параметр `reload` определяет, будет ли база сброшена и пересозданы все таблицы при старте
  3. настройки логера. `logfile` определяет имя файла, куда будут записываться логи, при значении `stdout` логи будут выводиться в консоль. `loglevel` задает уровень логирования
- `domain\model` содержит описание моделей. Стракт теги написаны так, что можно миграцию изменить с goose на GORM
- `logger` содержит файл создания структуры логера. Используется текстовый вариант `slog`
- `storage` содержит файл создания структуры для подключения к базе данных, миграций и методами для работы с БД. Для работы с БД использован `GORM`, для миграций - `goose`.
- `web` содержит файлы для создания роутера (`mux`) и хендлера для обработки запросов. Каждый метод хендлера выделен в отдельный файл. Использован стандартный `net/http`. Здесь же один файл с тестами с использованием пакета `testify`.
- `migrations` содержит файлы go для миграций БД.

## Принятые решения при реализации проекта
- При перемещении департамента, сделал возможным переместить на верхний уровень (без родителя), для этого `parent_id` нужно указать равным 0. При перемещении также осуществляется проверка на дубликаты имен с другими подразделениями данного уровня.
- При удалении департамента в режиме `reassign` не задано, что делать с дочерними подразделениями. Поэтому сделал так, что при наличии дочерних подразделений перемещение невозможно.
